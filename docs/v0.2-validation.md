# RimLazy 0.2.0 联合验收

测试日期为 2026-11-12，游戏构建为 Windows RimWorld 1.7.5005 rev1082。下表使用实际游戏、Harmony、RimLazy 和只随测试加载的探针。五个 DLC 均启用。五个场景均停用了外部 Complex Jobs 和 PriorityMaster，使用独立运行目录、配置和存档。

| 场景 | 实际工作列 | 验证结果 |
| --- | ---: | --- |
| 默认配置 | 44 | RimLazy 提供 21 个细分岗位。与另一次加载原 Complex Jobs 所得到的目录逐一对照，156 个 WorkGiver 的岗位归属完全一致。 |
| 导入玩家原有的两个模组设置 | 47 | 从 XML Extensions 导入黑客、救援和机械体维护，其余 12 个可选岗位关闭。PriorityMaster 的六档、默认 3 和渐变配色导入后写入 RimLazy 配置。另用九档、默认 7 与自定义色检验导入确实读取源值。 |
| 打开全部可选岗位 | 59 | 21 个默认和 15 个可选岗位均由 RimLazy 提供。预览、分配、真实工作表写回、保存重开与撤销通过。 |
| 读入 v0.1 与外部 Complex Jobs 建立的六档旧测试档 | 44 | 85 个历史差分逐格读回，在新版执行撤销和重新分工后完成保存、重开验证。 |
| 用全开岗位配置打开新版默认布局的存档 | 59 | 三个殖民者原有各格均按工作 ID 还原，新增加的列为 0。旧撤销记录仍能执行，新的分工也可保存重开。 |

游戏测试向原版工作格发送左右键和向原版列头发送 Shift 点击，核实 4→5→6、整列调整、禁用后循环、颜色和提示。在游戏实际排好序的正常任务列表中，第五档工作排在第六档之前。测试还在游戏工作页调到 99 档，检查已有六档值会阻止将上限降至四档。方案生成时考虑每个细分岗位的资格和能力，修改相关技能后对应岗位的评分随之改变。

18 项离线测试全部通过。其中包括物流拆成三列后仍共享原分组预算，以及没有手术任务时保留最低档候补、把当前工时释放给护理。五个游戏场景的错误日志均为空，核心和游戏程序集的 SHA-256 均与发行包中的文件相同。
