# RimLazy 0.2 与其他工作模组

RimLazy 在 RimWorld 1.7 上使用 Harmony 修改标准工作页。新配置默认允许 1–6 档，默认启用值为 3。模组设置允许选择最高 1–99 档、默认值、渐变或逐档颜色。玩家可以在原版工作页点格子、Shift 点列头，也可以用分工页计算和撤销。

## 接管现有配置

- 首次启动会读取 PriorityMaster 的旧设置，以及 XML Extensions 记录的 Complex Jobs 开关，保存在 RimLazy 自己的配置中。已有的 RimLazy 配置优先。
- 默认 21 个细分岗位和 15 个可选岗位沿用原工作 `defName`，保留当前工作列、玩家映射和锁的关联。可选岗位和规则下次启动游戏时生效。其他 MOD 新增的可见工作列也会进入分配器。
- 新存档为每个殖民者保存按工作 ID 命名的优先级。有这份数据时，即使岗位顺序改变，以前的值也能按名称恢复。新增的列从关闭开始，临时去掉的列保留数值以便再次启用。以前只有数值顺序的存档首次由原版读取；升级当次保留原有岗位配置和加载顺序有助于正确对应。已实测的迁移范围见[验收记录](v0.2-validation.md)。
- 如果存档仍在使用第六档，将范围降至四档会提示先在工作页调整相关格子。预览后发生岗位、档数、锁定或人员资格变化时，应用会要求重新预览。撤销也会核对当前格值及可用档位。

## 工作定义与兼容

工作细分在游戏构建任务列表时生效。它影响普通工作表、实际派工、年龄限制以及相关配方绑定。任务归属按当前已安装内容中的稳定 ID 建立。护理和手术、维修和拆除、收获和播种都有各自的资格、能力评分和优先级。运行环境只有部分 DLC、机体或工作台时，适配只处理实际存在的定义。

| 环境 | 行为 |
| --- | --- |
| 安装 Harmony 和 RimLazy | RimLazy 提供细分、手动工作页档位与自动分配。计算时同类岗位共享预算，能识别的工作台、手术需求和设备限制会影响用工。开放式任务的工时为估计。 |
| 同时启用原 Complex Jobs | 外部模组负责工作列，RimLazy 跳过自带拆分，使用最终加载的工作定义分配人力。 |
| 同时启用 PriorityMaster | RimLazy 让出工作页修改；识别其已加载的设置接口时使用它的实际档位。上游旧版支持的游戏版本仍取决于作者。 |
| 其他整数档位提供者 | 工作表模组可调用 `StrategicWork.RimWorld.PriorityCompatibility.RegisterRange(packageId, getMaximum)` 注册当前有效上限。0 表示禁用，1 最优先。 |
| Fluffy Work Tab | 按小时、按子任务的排班与整列分工含义不同，RimLazy 提供预览并保护已有细分排班。 |

默认机制与部分可选项取自玩家已经使用的工作方式。实现和随包的定义由 RimLazy 提供。[原 Complex Jobs 的功能说明](https://steamcommunity.com/sharedfiles/filedetails/?id=2069684319) · [PriorityMaster 作者项目](https://github.com/Lauriichan/PriorityMaster)
