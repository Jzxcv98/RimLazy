# RimLazy 的玩家输入与自动分工设计

2026-11-12 设计稿，针对本机 RimWorld 1.7.5005 rev1082 和 RimLazy 0.2.0。本文取代上一稿的“玩家选择持续灵感”方案。下文描述拟实现的行为。网上攻略的版本、实际阅读记录、游戏方法和当前代码差距见[机制与资料核对](work-assignment-evidence-1.7.md)。

## 一、玩家看到什么

玩家进入「分工」时，只需要作两类决定。**我希望殖民地把劳力用在哪里？我愿意为培养人接受多少当期代价？** 首次可直接沿用预设。既有的订单、禁止事项、角色状态、灵感、装备和工位条件由系统读取。

| 玩家意图 | 界面与含义 | 默认与边界 |
| --- | --- | --- |
| 殖民地战略 | 沿用各方向的「最低工时占比」和「剩余工时权重」。方向是生存、建设、科研、工业、防务，工作列可由玩家改归属。 | 模板可编辑，所有方向均可为零。最低份额之和超过 100% 时按输入比例自动归一化，滑块保留原值。剩余权重全零时沿用玩家选择的保留或留空策略。 |
| 看重培养的程度 | 一个滑块「培养潜力」，显示“最多愿为培养让出本期预计表现的 X%”。0% 只优化当期表现。10% 意味着可以为有价值的成长考虑预计表现至少达到参考方案 90% 的安排。 | 随战略预设保存。建议初始用 0%，让首次预览成为清晰的当期基准。100% 也受资格、玩家锁定、安全/品质要求和战略覆盖约束。此处的百分比是估计代价上限，并非学徒占用的工时比例。 |
| 本次赶工（可选操作） | 临时把培养设为 0%，以眼下可用的工人、设备、当前配装和实际任务计算。要赶某个已有目标，可把焦点指向那一项。已有订单的指定人、数量和材料直接继承。 | 只影响本次主动计算，不覆盖常态预设，也不代表游戏的救火、战斗等应急派工。 |
| 玩家例外（按需） | 锁住某个人的某个工作格、保留整列、为新模组工作指定战略归属。 | 锁定优先。原版或其他 MOD 已定义的订单技能范围、允许区域、日程、强制穿戴、禁工等只配置一次。 |

六档或其他档数属于工作表设置。分配器自动读取有效范围。培养滑块、战略百分比和档位数字各有自己的单位。「预览」「计算并应用」「撤销」仍按地图、由玩家手动触发。没有灵感开关、“移速看重多少”、特性分数表、逐种族修正、每个台子的速度输入框，或要求玩家估计剩余有效时间的表单。

战略百分比以本期可分配的劳动时间为分母。设方向最低份额为 M、剩余权重为 W。当最低份额合计低于 100% 且权重总和大于零时，该方向的目标份额为 `M + (1 − ΣM) × W / ΣW`。最低份额合计超过 100% 时使用 `M / ΣM`，达到或超过 100% 时没有剩余资源。人员不足或没有订单时同时显示目标和可实现部分，保留差额。

**连续控制的例子。** 工人 A 是 20 级无火，B 是 15 级双火，其他条件相同。假设 A 一班能做 100 件合格品，B 能做 92 件，两人都满足订单要求。培养设为 0% 或 5% 时选 A。设为 10% 时 B 可以入选，条件是该任务有对应技能经验，且选择 B 确实产生有用成长。如果这批货两人都能按时足量完成，只比较需求范围内的产出，并考虑腾出来的时间还能做什么。实际判断以该工作真实速度、风险和品质为准，等级封顶、受伤等情况下不能只看 20 和 15 两个数。

## 三、从游戏快照到工作表

### 1. 生成任务机会，先判能不能做

在玩家按下计算时取固定快照。把工作列展开成一批代表性机会，例如做某种餐、在某台机器执行某张订单、把一批材料送到工位、收获一片已成熟的田。合并同路线、同配方或同类目标，记录估计来源。工作列是最后写回的单位，具体任务才是评估候选者的单位。

依次检查玩家锁定、永久及当前禁工、WorkGiver 所需能力、订单/配方门槛、指定人和半成品绑定、场地和资源。区域外、已禁止、缺原料、台子无电、病人已有预留等原因分别显示。不能做某一个订单的人仍可能做这一列的其他订单。读取休息、需求和日程估计可劳动时段。原版日程通过思考树改变工作的相对优先程度，不能把“工作”时段当成必然生产的每一分钟。

预览使用无副作用的读取或近似。不批量调用真实派工、预留或结算方法来试人。比如失败的原料搜索可能改写订单的下次检查时间，品质结算可能消耗灵感和随机数。未知模组的 WorkGiver 先使用公开的资格、标签和限制，无法证明的条件标为估计，关键资格不明时保留原格。实际开始任务仍由游戏判断。

### 2. 计算一个人完成一件工作的表现

先拆过程，再读在各阶段真正生效的属性。一次候选任务的预计时间可分为取料、走路、现场操作、交付和等待。产物数量、品质、失败/污染概率分别计算。没有相关结果的工作不套该项指标。跨工作只比较战略下定义的同类有效产出或标准工作量，优先满足玩家已有的订单和品质约束。

| 岗位/任务 | 游戏机制怎样进入估算 |
| --- | --- |
| 搬运、送货、补弹、救援 | 由起终点、通行条件和往返次数估算。每趟考虑可搬容量、物品单位体积和堆叠上限。原版抱起另一名角色还会改变步行耗时。搬一个不能堆叠的物件时，大容量未必省下一趟。 |
| 做饭、屠宰、制药、普通加工 | 每张配方读取自己的角色操作 Stat、工位因子、产量/效率及学习技能。烹饪同时看速度和污染，屠宰看速度和产出。下单者设定成品入库还是就地落地，会把运送时间分给不同的人。 |
| 医疗、护理、手术 | 护理有找食物、药物和走到病床的时间。治疗看施治速度和质量。手术结合合格医生、配方、病人、床与药估算常规成功率。只有一个好医生时，还要评价让其做护理而失去手术覆盖的代价。 |
| 种植、收获、采矿、深钻 | 看播种门槛、作物成熟/季节窗口、地块距离、当前可采目标和设备数量。收获普通植物和药用植物实际使用不同的产量属性。成功率、产量和操作速度分别进入结果。 |
| 建造、修理、拆除、工艺、艺术 | 看材料配送、现场工量、有效操作速度和适用的失败/品质机制。生产专家的持久品质效果可计入符合条件的产品。切石、普通墙、可评品质的家具分别处理。 |
| 科研、黑客、扫描 | 读取项目/目标和设备约束。科研进度直接取个人研究速度与研究台研究因子。扫描、黑客另查自己的工作驱动。没有可用研究台时显示工位缺口。 |
| 动物、社交、教学和杂务 | 驯服/训练概率结合对象与资格。狩猎还受射击、武器和路径影响。对社交、教学、清洁等分别查真实任务和使用的技能。不能从一个列名推定整班都给同一种经验。 |

**烹饪示例。** 可中毒的烹饪产物先过房间污染判定，再过厨师个人污染判定。若概率分别为 R、C，污染概率为 `R + (1−R)×C`。无其他修正时，厨艺 4 对应个人风险 1.5%，9 到 20 均为 0.1%。4 级厨师在清洁度 −3.5 的厨房约为 3.96%，在清洁度达到 −2 的厨房约为 1.5%。因此“换厨房”和“换厨师”是两种不同的改进，9 级与 15 级厨师之间也不能虚构一份食品安全优势。装了修改概率的 MOD，就按当前加载规则计算。食客的基因或免疫属于进食时的结果。[角色定义](D:/Steam/steamapps/common/RimWorld/Data/Core/Defs/Stats/Stats_Pawns_WorkRecipes.xml:138) · [房间曲线](D:/Steam/steamapps/common/RimWorld/Data/Core/Defs/Rooms/RoomStats.xml:292)

### 3. 自动处理持续灵感、一次性灵感、装备与光环

**持续生效的属性变化随属性自动进入计算。** `StatWorker.GetValueUnfinalized` 已把当前 `InspirationDef` 的加数和乘数合入所查询的 Stat。`Pawn.TicksPerMove` 用生效的 `MoveSpeed`，所以移动狂热已经进了步行时间。工作狂热随真正使用 `WorkSpeedGlobal` 的属性传导，射击狂热随射击属性进入对应任务。读取实时值后不会再按效果名乘第二次。新增模组的持续加成能通过正常属性入口传导时，同样无需玩家登记。[原版灵感定义](D:/Steam/steamapps/common/RimWorld/Data/Core/Defs/InspirationDefs/Inspirations.xml)

实际预测按规划期内有工作机会的时段计算。近期比较建议从当前时刻向前看一个游戏日，结合每人的作息。已有明确任务目标和期限时使用该范围。已知灵感会在中途到期的，分别估计到期前后可完成的工作。当前片段用实况值，后续片段在已知来源和原计算顺序下重估。位置采样也要对上任务，研究员在卧室的光照不代表研究台的光照。有效期不明时记录当前读数与不确定性。预览显示时间窗口和影响，不提供给玩家选择是否认识某种灵感的开关。

**移速的影响取决于有多少工作在走路。** 假设其他条件不变、全程受移动狂热影响、走路速度 ×1.4，原来 70% 时间在路上的任务，预计吞吐提升约 25%。原来只有 10% 时间在路上的任务，提升约 3%。两个比例用来说明算法，并非固定岗位权重。若一条长路线经过不同地形、天气或设施范围，按代表路段和覆盖时间估算。

**一次性机会留给玩家。** 创作、手术、驯服、招募、交易这类用一次就消耗的机会，从自动排名目标中排除。做普通品质预测时保留角色自身技能与生产专家的持续效果，排除一次性创作的额外品质。代码有两种入口。有的效果只在结算函数触发，有的也会进入面板，例如交易灵感改变交易属性，成交时又会消耗。普通工作表能保证的是“仅获得某项一次性灵感，RimLazy 的方案不变”。具体工人实际完成了相应物件时，游戏仍按原版规则结算。珍贵作品可由玩家指定工人。

**个人能力与可移交资源同时计算，但不混为一种优势。** 常态分工比较同一任务与参考装备/工位条件，保留种族、有效基因、身体、安装的义肢和持久角色的真实差异。当期可执行方案尊重实际穿戴和工位。可换的厨师帽不永久算给当前佩戴者。如果一种族才能穿、装备被锁或换装会导致不能工作，这些条件必须保留。同样一顶帽子只能给一个人。可以在首轮分工后按边际收益建议配装，若稀缺工具足以改变主业，只复核受影响的人选。仅推荐的换装不得计入“现在即可兑现”的产能。

本机下载的鼠族厨师帽同时影响烹饪速度和中毒属性。另一个模组的暖辉建筑会通过人物状态提高意识并降低移速。连接制造台的分析仪则直接改台子的速度。对可追溯修正在原属性计算阶段替换场景。不从经过曲线、封顶的最终数值硬减装备说明。未知的模组自定义算法应区分“可读取的实况”和“尚不能准确归因的个人参考值”。若候选人排序完全依赖这一未知项，保留已有安排并说明原因。预览不在真实殖民者身上脱衣、删状态。[厨师帽](D:/Steam/steamapps/workshop/content/294100/1578693166/1.6/Defs/ThingsDefs/Apparel_Various.xml:927) · [暖辉状态](D:/Steam/steamapps/workshop/content/294100/3159926804/1.7/Defs/HediffDefs/Hediff_Building.xml:20) · [制造台设施补丁](D:/Steam/steamapps/workshop/content/294100/3745770950/1.7/Patches/BT_MultiAnalyzerFabricationBench.xml:6)

### 4. 单独估培养价值，再做全殖民地匹配

从任务实际使用的技能、可拿到经验的操作时间、配方学习因子、当前学习倍率和剩余成长空间估算培养收益。无火、单火、双火在本机构建的普通学习基础倍率分别为 0.35、1、1.5。实际学习还有个人和当日学习饱和等影响。优先看预计成长能否让殖民地多出一位合格替补、跨过有用门槛或改善将来的任务结果。搬材料的路途不自动算作制作经验。无相应经验的任务培养收益为零。技能对当前表现的影响已经被对应属性、资格或品质机制捕捉时，避免再乘一遍技能等级。

先生成只看当期表现的可行参考方案。在相同的需求、约束和可实现战略覆盖下，再比较培养型人选。每个有投入的方向使用自身固定的任务构成和可比度量来校验玩家的代价上限。避免拿科研的额外产出去掩盖食品的缺口。无法有效计量的岗位不显示伪精确百分比。预览同时给参考产出、候选产出和预计成长。差别很小或不确定时优先保留现有分工。

实现上可给每种任务保留独立的需求上限及合格标准，用本期预计能交付的合格数量比较同一任务。混合任务可按固定的参考工作量折算，权重在比较两套方案期间保持一致。先产出同一快照下的当前表现参考矩阵，再用相同的离散工作顺序评估培养方案。设本方向参考表现为 B，培养容忍度为 p，有效候选需满足 `候选预计表现 ≥ (1−p) × B`。对包含硬性期限的指定任务还要单项守住期限。p 为零时沿用当期方案，不因火焰打破平手。B 为零时报告不可行原因，不凭空制造练习工时。这个比较针对实际可写的工作表，不能只在连续分配模型里达标。

全局分配同时计人力、共享工位、有限订单和必要后备。先按战略分工时，再在工作族内比较细分岗。把搬运拆成送货、装载等多列不会凭空增加物流需求。输入为零时不加隐藏保底。无工位或任务耗尽时报告缺口，正权重、未来可能有活的岗位可保留后备，后备不计作已完成的工时。

### 5. 把方案转换成游戏实际会执行的档位

原版的思考树决定殖民者此刻是否进入工作分支。`Pawn_WorkSettings` 将已启用的工作列按个人档位和自然优先级排序，列内还有 WorkGiver 的顺序。普通工作和紧急工作有各自的筛选路径。`JobGiver_Work` 再找合格、有目标、可执行的任务。一个人的“科研 1、搬运 6”不能兑现为固定的科研工时百分比。

按运行中的 1–N 档生成候选矩阵、保留锁定，以只读代理估算实际顺序下的可执行任务。按事件推进到完成、工位释放或可预见状态到期，校正离散化引起的偏差。输出目标、预计工时、可交付结果、培养代价、不确定项和变更格。玩家确认应用时复查会改变方案的关键前提，包括格值、资格、身份、档数、关键设备与状态。明显过期时重新预览。一次写回并保留撤销记录，无需后台逐 Tick 重排。

| 纯算法核心 | 输入每个“人 × 任务情景”的可执行性、阶段耗时、结果/风险和独立的培养收益。输出只看当期的参考方案、允许培养的方案、离散矩阵和诊断。 |
| 游戏写回 | 只改玩家选定范围内、未锁定、通过复核的优先级。自动估计与实际游戏写回分开。 |

## 五、下一轮按行为验收

| 改变的条件 | 应得结果 |
| --- | --- |
| 同一人获得移动狂热，没有任何 UI 操作 | 下次主动计算自动读取新移速。远距离送货受益大于就地加工。属性中已有的倍率只计一次，临近到期只计覆盖的工作段。 |
| 仅为同一生产专家增加创作灵感，或仅启用一次性交易收益 | 自动工作矩阵一致。预览前后灵感、游戏随机状态、任务预留和订单重试时间保持一致。 |
| 20 级无火和 15 级双火互换火焰 | 当期条件不变且培养为零时，结果不变。开启培养后，只对确有经验、质量达标且在允许代价内的工作改变人选。 |
| 同一厨师换脏厨房，或两人对换厨师帽 | 环境风险随厨房走，装备收益随实际可用的帽子走，个人稳定能力不被永久改写。 |
| 改一次原料半径、指定工人、成品落点或研究台电力 | 下次计算自动继承。缺料、无人能接、搬运劳动转移、设备不可用分别给出不同诊断。 |
| 一张台、多人、工作列由 44 扩到 59 或档位从 4 改为 6 | 共享容量只算一次。新列从运行时发现，矩阵按实际档位重估。同一快照和偏好得到同一结果。 |
| 所有战略最低值/权重为零，或开启外部来源不可辨的 MOD | 执行玩家已选的余量策略。未知项可见，确定性与锁定仍有效。 |
