# RimLazy · 殖民地分工

RimWorld 1.7 的本地工作分配 MOD。v0.2 内置细分岗位和可配置的工作优先级，默认六档。你决定生存、建设、科研、工业和防务需要的人力，RimLazy 按当前地图上的工作、殖民者能力和可用工位生成工作表。需要重新分工时点击计算即可。

## 怎么用

1. 将发行包中的 `RimLazy` 文件夹放入游戏的 `Mods`，启用 **Harmony** 和 **RimLazy · Colony Work Planner**，Harmony 放在前面。
2. 进入殖民地，在原版「工作」页勾选手动优先级，再点底栏 **分工**。可以直接使用均衡预设，也可以调整每个方向的最低工时占比和剩余工时权重。两者都允许为零。
3. 点 **预览分配** 查看预计投入、缺口和逐格改动。需要保护某个格子时，在「优先级锁定」中选殖民者并勾选工作；整列不想交给 MOD，就在「工作类型」中选择「保留原值」。
4. 点 **计算并应用** 写回。**撤销上次应用** 能跨保存和读档；若其他人或 MOD 已改了相关格子，会提示冲突。换人、受伤、添工位或换战略后，按需要再算一次。

## 工作列和档位

- 默认增加 21 个细分岗位，涵盖护理、手术、训练、屠宰、维修、拆除、收获、钻探、制药、机械加工、精密制造、送货等工作。模组设置还能选择 15 个额外岗位，包括黑客、救援和机械体维护。修改工作细分后重启游戏。
- 原版「工作」页支持左右键调节和 Shift 点列头批量调整。`0` 表示关闭，`1` 最高。模组设置中可以选择 1–99 档，初始设置为六档、默认值 3，并可调整显示颜色。首次使用时会读取已有的 PriorityMaster 配色、档数和旧 Complex Jobs 细分设置。
- 「工作类型」页允许覆盖战略归属。救火、就医等工作默认保留原值。已有外部工作表扩展的处理见[兼容说明](docs/compatibility.md)。

## 这张表怎么算

先按最低占比预留劳力，再按权重分剩余量。每个战略先分到各类工作，再在同类的细分岗位中分配。例如送货、装载和普通搬运共享物流预算，各自挑选合适人选。对手术看医疗技能、手术速度和成功率，对护理更重视走动效率，对收获同时考虑植物工作速度与收获产量。算法按实际订单和可识别的工位限制投入，按工作顺序估算主业和后备的效果。正权重岗位暂时无任务时，可以保留一名最低档候补。

例如三名同班工人只有一张可用研究台时，不能同时安排三人科研。结果中的百分比是可劳动人力的估计，不是游戏保证的钟表时间。首版不追踪每个材料堆、路径、逐小时作息或每个第三方订单；部分工作需求属于估计。MOD 不会创建订单、接管战斗或在后台改表。

## 构建与验证

安装 .NET 10 SDK 后，在仓库根目录运行：

```powershell
./scripts/test.ps1
./scripts/build-mod.ps1 -GameDir 'D:/Steam/steamapps/common/RimWorld'
```

构建脚本读取本机 1.7 游戏程序集及同一 Steam 库的 Harmony 1.7。非 Steam 布局可将环境变量 `HARMONY_DIR` 指向 Harmony 模组根目录。发行包在 `.artifacts/RimLazy-0.2.0.zip`。核心测试可独立运行。Windows 上可用 Python 3.12+ 执行隔离实机测试。

```powershell
python scripts/smoke-game.py --game 'D:/Steam/steamapps/common/RimWorld'
python scripts/smoke-game.py --game 'D:/Steam/steamapps/common/RimWorld' --all-splits
```

测试运行在临时游戏副本和隔离存档中。[v0.2 验收](docs/v0.2-validation.md) · [v0.1 验收](docs/v0.1-validation.md) · [初期设计](docs/phase-0.md)
