# RimLazy · 殖民地分工

RimWorld 1.7 的本地工作分配 MOD。你决定殖民地要花多少人力在生存、建设、科研、工业和防务上；RimLazy 按当前地图的殖民者、能力和工作列生成一张工作表。只在你点击时计算，不需要其他 MOD 或在线服务。

## 怎么用

1. 将发行包中的 `RimLazy` 文件夹放入游戏的 `Mods`，然后在游戏模组列表中启用 **RimLazy · Colony Work Planner**。
2. 进入殖民地，在原版「工作」页勾选手动优先级，再点底栏 **分工**。可以直接使用均衡预设，也可以调整每个方向的最低工时占比和剩余工时权重。两者都允许为零。
3. 点 **预览分配** 查看预计投入、缺口和逐格改动。需要保护某个格子时，在「优先级锁定」中选殖民者并勾选工作；整列不想交给 MOD，就在「工作类型」中选择「保留原值」。
4. 点 **计算并应用** 写回。**撤销上次应用** 能跨保存和读档；若其他人或 MOD 已改了相关格子，会提示冲突。换人、受伤、添工位或换战略后，按需要再算一次。

## 工作列和档位

- 按当前地图实际可见的工作定义发现工作列。Complex Jobs 的细分列和原版列一样参与分配；自动分错可以改，无法归类的列默认保留。救火、就医等列默认也保留。
- 优先级采用当前工作表的档位，`0` 表示关闭，`1` 最高。如果扩展没有公开档位上限，而分工仍只显示 4 档，在该扩展的工作表里将**一名殖民者的一个格子**设成 6，再回「分工」预览。设置里的上限只用于限制已识别的范围。
- 兼容的是能通过游戏工作设置读写的**整列整数优先级**。按小时独立排班、WorkGiver 子列以及自有存储的工作表，需要专门对接。详见[兼容说明](docs/compatibility.md)。

## 这张表怎么算

先按最低占比预留劳力，再按权重分剩余量。算法排除不能执行的任务，考虑技能、激情、身体能力、岗位速度、能识别的工位或生产单限制，将人力分给多个战略；再把分配结果换成当前档位的主业和后备，按游戏的工作顺序估算效果。已有启用的锁定格也参与估算。正权重工作暂时无任务时，可保留最低档候补，不把候补算作当前工时。

例如三名同班工人只有一张可用研究台时，不能同时安排三人科研。结果中的百分比是可劳动人力的估计，不是游戏保证的钟表时间。首版不追踪每个材料堆、路径、逐小时作息或每个第三方订单；部分工作需求属于估计。MOD 不会创建订单、接管战斗或在后台改表。

## 构建与验证

安装 .NET 10 SDK 后，在仓库根目录运行：

```powershell
./scripts/test.ps1
./scripts/build-mod.ps1 -GameDir 'D:/Steam/steamapps/common/RimWorld'
```

构建脚本使用指定 1.7 安装的程序集进行编译。输出 `.artifacts/RimLazy-0.1.0.zip` 只含 MOD 的 DLL、定义与翻译。核心测试不需要游戏。Windows 上可用 Python 3.12+ 运行隔离实机测试：

```powershell
python scripts/smoke-game.py --game 'D:/Steam/steamapps/common/RimWorld'
python scripts/smoke-game.py --game 'D:/Steam/steamapps/common/RimWorld' --complex-jobs 'D:/Steam/steamapps/workshop/content/294100/2069684319'
```

测试运行在临时游戏副本和新地图中；测试 DLL 不随发行包分发。[版本验收](docs/v0.1-validation.md) · [初期设计](docs/phase-0.md) · [原始 handoff](RimWorld_Codex_Development_Handoff_2026-11-12.md)
