# RimLazy · 殖民地分工

RimWorld 1.7 的本地工作分配 MOD。v0.3.2 支持培养潜力和单次赶工，内置细分岗位和可配置的工作优先级，默认六档。你决定各战略需要的人力，以及愿意为培养让出多少当期表现。RimLazy 根据地图上的工作、殖民者和设备生成工作表。

## 怎么用

1. 将发行包中的 `RimLazy` 文件夹放入游戏的 `Mods`，启用 **Harmony** 和 **RimLazy · Colony Work Planner**，Harmony 放在前面。
2. 进入殖民地，在原版「工作」页勾选手动优先级，再点底栏 **分工**。可以直接使用均衡预设，也可以调整每个方向的最低工时占比和剩余工时权重。两者都允许为零。最低投入总和超过 100% 时会按比例归一化。比如输入 15、5、100 后，目标占比分别为 12.50%、4.17%、83.33%。原始数值保留在预设中。
3. 调整 **培养潜力**，然后点 **常态预览**。默认 0% 使用当期表现参考方案。10% 表示各有投入且可比较的战略方向最多允许预计表现下降 10%，实际让出的可以更少。培养值来自适用任务的学习机会。结果页显示参考方案、本案、训练收益和逐格变化。
4. 临时需要冲产量，点 **本次赶工**。它按接下来一个游戏小时、实际配装和零培养计算。可选一个方向取得本次剩余劳力，原战略的最低份额继续有效。检查预览后点 **应用赶工方案**；日常方案用 **计算并应用常态方案**。培养滑块与命名预设仍保存原值。
5. 在「优先级锁定」保留单格，在「工作类型」保留整列。**撤销上次应用** 支持存读档。若其他人或 MOD 已改动相关格子，会提示冲突。

## 工作列和档位

- 默认增加 21 个细分岗位，涵盖护理、手术、训练、屠宰、维修、拆除、收获、钻探、制药、机械加工、精密制造、送货等工作。模组设置还能选择 15 个额外岗位，包括黑客、救援和机械体维护。修改工作细分后重启游戏。
- 原版「工作」页支持左右键调节和 Shift 点列头批量调整。`0` 表示关闭，`1` 最高。模组设置中可以选择 1–99 档，初始设置为六档、默认值 3，并可调整显示颜色。首次使用时会读取已有的 PriorityMaster 配色、档数和旧 Complex Jobs 细分设置。
- 「工作类型」页允许覆盖战略归属。救火、就医等工作默认保留原值。已有外部工作表扩展的处理见[兼容说明](docs/compatibility.md)。

## 这张表怎么算

先按战略和工作族分配人力，再把连续分工转换成实际档位。系统以零培养矩阵为参考，对候选工作表重新模拟岗位顺序、有限订单与共享工位，分别检查各方向的预计当期代价。火焰、学习率、有效操作工时与成长空间只用于培养。未知任务无法可靠比较时，可比部分和不确定项分开显示。

常态分工看一个游戏日的可用劳力和任务条件，剥离可识别的可转移装备优势。赶工使用当前穿戴。持续灵感来自游戏已生效的属性，按剩余有效时长估计，一次性创作、手术等机会留给玩家。烹饪估算个人与厨房污染风险，已知生产单读取指定工人、原料半径、件数和成品去向。工位采样、较长路线、开放式工作、用药与自定义工作效果存在估算误差。装备建议遵守穿戴限制和物品占用，由玩家自行调拨。

## 构建与验证

安装 .NET 10 SDK 后，在仓库根目录运行：

```powershell
./scripts/test.ps1
./scripts/build-mod.ps1 -GameDir 'D:/Steam/steamapps/common/RimWorld'
```

构建脚本读取本机 1.7 游戏程序集及同一 Steam 库的 Harmony 1.7。非 Steam 布局可将环境变量 `HARMONY_DIR` 指向 Harmony 模组根目录。发行包在 `.artifacts/RimLazy-0.3.2.zip`。核心测试可独立运行。Windows 上可用 Python 3.12+ 执行隔离实机测试。

```powershell
python scripts/smoke-game.py --game 'D:/Steam/steamapps/common/RimWorld'
python scripts/smoke-game.py --game 'D:/Steam/steamapps/common/RimWorld' --all-splits
```

测试运行在临时游戏副本和隔离存档中。可用 `--player-package` 指向已解压的发行目录以复核运行的 DLL。[0.3.2 实玩日志回归](docs/v0.3.2-validation.md) · [0.3.1 手测问题回归](docs/v0.3.1-validation.md) · [v0.3 验收](docs/v0.3-validation.md) · [分工设计](docs/work-assignment-factors-1.7.md) · [v0.2 验收](docs/v0.2-validation.md)
